## 1. The tools and what they do

| Tool | What it is | Why we use it |
|---|---|---|
| **Node.js** | JavaScript runtime outside the browser | Runs Next.js, build tools, scripts |
| **pnpm** | Package manager (like npm, but faster and stricter) | Installs dependencies, locks versions |
| **Git** | Version control | Tracks every change, enables branches and PRs |
| **GitHub CLI (`gh`)** | Command-line access to GitHub | Create repos, PRs, review — without a browser |

| **Tailwind CSS** | Utility-first CSS | Styling without writing custom CSS |

| **PostgreSQL** | Relational database | Where all persistent data lives |
| **Neon** | Hosted Postgres (free tier) | Production database, no server to manage |

**Mental model:** Node runs the app. pnpm installs libraries. Git tracks changes.
GitHub stores the repo. Next.js builds the app. Prisma talks to Postgres.

## 2. The workflow we used

Every change followed this loop:

```
1. Create a branch          → git checkout -b feat/whatever
2. Make changes             → edit files
3. Stage changes            → git add <files>
4. Commit with a message    → git commit -m "..."
5. Push to GitHub           → git push -u origin feat/whatever
6. Open a Pull Request      → gh pr create
7. Merge when ready         → gh pr merge --squash --delete-branch
8. Sync local main          → git checkout main && git pull
```

**Why branches and PRs?** Even when working alone, they:
- Keep `main` always working
- Create a reviewable record of what changed and why
- Match how real teams work
- Score points in BuildIt (Ownership, Code Review)

**Never commit directly to `main`.** Every change goes through a branch.

## 3. The errors we hit, and what each one actually meant

### Error A: `ERR_PNPM_RESOLVING_NPM_RESOLVER_NETWORK_ERROR`

**What it looked like:**
```
Failed to fetch https://registry.npmjs.org/@prisma/client
error decoding response body: operation timed out
```

**What it means:**
The package manager couldn't download a library from npm's servers. Not a
code problem — a network problem. TLS handshake failed, or the connection
dropped mid-download.

**Fixes tried:**
1. Increase timeouts:
   ```
   pnpm config set network-timeout 600000
   pnpm config set fetch-retries 5
   ```
2. Switch to a mirror:
   ```
   pnpm config set registry https://registry.npmmirror.com
   ```
3. Install packages one at a time instead of all at once
4. Retry. Sometimes the network just settles.

**Lesson:** Never blame your code for a network error. Read the error
carefully — "timeout" and "fetch" are network words. "Syntax" and "type" are
code words.

---

### Error B: `ERR_PNPM_IGNORED_BUILDS`

**What it looked like:**
```
Ignored build scripts: esbuild@0.28.2, msgpackr-extract@3.0.4, workerd@...
```

**What it means:**
Some packages run a "postinstall script" when installed — they compile native
code, download binaries, etc. pnpm blocks these by default for security (a
malicious package could run any command on install). You have to explicitly
say "yes, run this one."

**Why this exists:**
Supply chain attacks. If a package you install is compromised, its postinstall
script can steal your data. pnpm makes you opt in per package.

**The fix:**
pnpm reads a file called `pnpm-workspace.yaml` and looks for:

```yaml
allowBuilds:
  esbuild: true
  prisma: true
  '@prisma/engines': true
  workerd: false
```

- `true` = "run this package's install scripts"
- `false` = "block them"

We set Prisma-related packages to `true` (they need to download their query
engine) and `workerd` to `false` (we don't use Cloudflare Workers).

**Lesson:** When a package manager blocks something, don't just disable the
safety. Read what's being blocked and decide per package.

### Error C: `fatal: Authentication failed for 'https://github.com/...'`

**What it looked like:**
```
remote: Invalid username or token. Password authentication is not supported.
fatal: Authentication failed for 'https://github.com/Vicgrace01/...'
```

**What it means:**
Git tried to push over HTTPS using a username and password. GitHub stopped
accepting passwords for Git operations in 2021. You need either:
- A Personal Access Token (PAT), or
- SSH keys

**The fix we used — SSH:**

1. Generate a key:
   ```bash
   ssh-keygen -t ed25519 -C "your-email@example.com"
   ```
2. Add it to GitHub:
   ```bash
   gh ssh-key add ~/.ssh/id_ed25519.pub --title "My Ubuntu"
   ```
3. Test:
   ```bash
   ssh -T git@github.com
   # Hi Vicgrace01! You've successfully authenticated...
   ```
4. Switch remote from HTTPS to SSH:
   ```bash
   git remote set-url origin git@github.com:Vicgrace01/q-not.git
   ```
5. Push:
   ```bash
   git push -u origin feat/foundation
   ```

**Lesson:** HTTPS + password is dead for Git. Use SSH. Set it once, forget it
forever.

### Error D: `fatal: A branch named 'feat/foundation' already exists`

**What it means:**
You already created this branch in an earlier command. `git checkout -b`
creates a new branch; if the name is taken, it fails.

**Fixes:**
- Switch to the existing branch: `git checkout feat/foundation`
- Delete and recreate: `git branch -D feat/foundation && git checkout -b feat/foundation`

**Lesson:** `git branch` lists existing branches. Check before creating.

### Error E: `Prisma schema validation - Error code: P1012` — `url is no longer supported`

**What it looked like:**
```
error: The datasource property `url` is no longer supported in schema files.
Move connection URLs for Migrate to `prisma.config.ts`
```

**What it means:**
Prisma 7 changed where the database URL lives. It used to be inside
`schema.prisma`:

```prisma
datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")   ← old way
}
```

Now the schema only declares the provider. The URL goes in a separate config
file called `prisma.config.ts`:

```ts
import { config } from "dotenv";
config({ path: ".env.local" });
config();

import { defineConfig, env } from "prisma/config";

export default defineConfig({
  schema: "prisma/schema.prisma",
  migrations: { path: "prisma/migrations" },
  datasource: { url: env("DATABASE_URL") },
});
```

**Why Prisma made this change:** Separating config from schema makes it easier
to have multiple environments (dev, staging, prod) and to keep secrets out of
version control.

**Lesson:** When a library releases a major version (Prisma 6 → 7), breaking
changes happen. Read release notes. Check the docs for the version you're
actually using.

### Error F: `PrismaConfigEnvError: Cannot resolve environment variable: DATABASE_URL`

**What it means:**
The config file tried to read `DATABASE_URL` from environment variables, but
nothing had loaded the `.env.local` file yet. `dotenv` is the tool that reads
`.env` files and puts their contents into `process.env`.

Two problems compounded here:
1. `import "dotenv/config"` only loads `.env`, not `.env.local`.
2. Even when dotenv is installed, the import has to run *before* the code that
   reads the env var.

**The fix:**
```ts
import { config } from "dotenv";
config({ path: ".env.local" });
config();

// now use env("DATABASE_URL") below
```

Calling `config()` twice is intentional:
- First call: load `.env.local` (developer-specific)
- Second call: load `.env` if it exists (CI/production fallback)

**Lesson:** Environment variables don't exist until something loads them.
Order matters in a config file — imports run top to bottom.

### Error G: `The relation field 'operator' on model 'Driver' is missing an opposite relation field on the model 'Operator'`

**What it looked like:**
```
error: Error validating field `operator` in model `Driver`:
The relation field `operator` on model `Driver` is missing
an opposite relation field on the model `Operator`.
```

**What it means:**
In Prisma, relations are always **two-way**. If `Driver` has `operator Operator`,
then `Operator` must have `drivers Driver[]`. Prisma refuses to guess.

**The fix:** Add the back-reference.
```prisma
model Operator {
  // ...
  drivers Driver[]   ← added
}

model Driver {
  // ...
  operatorId String
  operator   Operator @relation(fields: [operatorId], references: [id])
}
```

**Lesson:** Prisma relations are always pairs. Every `belongs-to` needs a
`has-many` on the other side. `prisma format` will try to auto-add missing
pairs.

### Error H: Pasting code into the terminal instead of into nano

**What it looked like:**
```
-bash: syntax error near unexpected token `('
Command 'import' not found...
A: command not found
```

**What it means:**
The terminal runs shell commands (`ls`, `git`, `pnpm`). It does **not** run
JavaScript, TypeScript, JSX, or YAML. When you paste code into the terminal,
bash tries to interpret it as shell commands and fails everywhere.

**The fix:** Code goes in an editor. Commands go in the terminal.

- Open editor: `nano path/to/file.ts`
- Paste code inside nano
- Save: `Ctrl+O`, `Enter`
- Exit: `Ctrl+X`
- Run commands back in the terminal

**Lesson:** Before pasting, ask: "Is this a shell command or code?" If it has
`import`, `function`, `{`, `}`, `=>`, or a semicolon at the end — it's code.
Editor, not terminal.

### Error I: Pasting code with a trailing `^[[200~` and `^[[201~`

**What it looked like:**
```
^[[200~git add .
git commit -m "..."^[[201~
```

**What it means:**
Those escape sequences are "bracketed paste mode." The terminal uses them to
know when you're pasting vs typing. If pasted content includes the markers
literally (instead of the terminal consuming them), your paste got mangled.

**Fix:** When pasting multi-line commands, paste one line at a time, or use
`Ctrl+Shift+V` (Ubuntu terminal's explicit paste).

**Lesson:** Terminals have quirks. If paste looks weird, retype the line.

## 4. Concepts you now know (or were introduced to)

- **Package manager vs runtime** — pnpm installs; Node runs.
- **Branch, commit, PR, merge** — the core Git loop.
- **SSH authentication** — how to identify yourself to GitHub securely.
- **Supply chain security** — why `allowBuilds` exists.
- **Environment variables** — config that lives outside the code.
- **ORM** — an object-relational mapper (Prisma) that lets you write
  TypeScript instead of SQL.
- **Schema-first design** — define your data model, generate code from it.
- **Bidirectional relations** — how ORMs model foreign keys.
- **Adapter pattern** — hide the implementation behind an interface so you can
  swap providers later (WhatsApp, payments, SMS).
- **Idempotency** — a request that produces the same result whether run once
  or many times (important for webhooks).
- **Race condition** — two operations that conflict when run at the same time
  (the seat-race problem).

## 5. Reading GitHub URLs and PRs

```
https://github.com/Vicgrace01/q-not
           └─ owner   └─ repo

https://github.com/Vicgrace01/q-not/pull/1
                                  └─ PR number
```

When a PR is merged with `--squash`, all its commits become **one commit** on
`main`. This keeps history clean. The PR itself stays visible forever for
reference.

`gh pr view 1` — see PR #1
`gh pr list --state all` — all PRs, open and closed
`gh pr merge 1 --squash --delete-branch` — merge and clean up
